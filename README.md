# WinScope Monitor

Windows 进程、线程与端口监控工具。

一个纯 Python 标准库实现的 Windows 桌面监控工具，统一查看进程、线程与 TCP/UDP
端口占用。它用 tkinter 做界面，通过 PowerShell/CIM 与 ctypes 读取真实的进程、
线程与端口信息，并对每个进程/端口给出来源线索与中文用途解释。

除监控与展示外，工具还允许在**用户明确点击并二次确认**后结束选中的进程或线程；
**端口页只读，不提供**关闭端口、停止监听或任何网络修改动作。工具同样**不提供**
暂停、注入、提权或后台驻留等能力。

## 快速开始

双击 [run_monitor.bat](run_monitor.bat)，或在命令行中运行：

```bat
python thread_monitor.py
```

建议使用 Python 3.8 及以上版本。程序只依赖标准库，不需要 `pip install`。

验证进程/线程数据层（不打开窗口）：

```bat
python thread_monitor.py --self-test
```

验证端口数据层（不打开窗口）：

```bat
python port_monitor.py --self-test
```

## 功能

- 进程列表：PID、名称、父 PID、线程数、进程创建时间、可执行路径、来源线索、
  简要用途。
- 线程列表：选中进程后展示线程 ID、线程状态、等待原因、优先级、线程创建时间
  （能取则取，取不到显示“未知”）。
- 端口占用：协议、本地地址/端口、远端地址/端口、状态、PID、进程名、父 PID、
  路径、简要用途；点击端口行显示来源路径、父进程、签名与用途依据，并说明
  “端口仅属于进程，不代表线程”。
- 来源线索：路径是否位于 `System32` / `SysWOW64` / Windows 目录；选中进程或
  点击端口行时按需读取代码签名（有效/未签名/异常）与签署者。
- 中文用途解释：依据透明、确定性的规则生成，无法证实的内容明确显示
  “未知/需人工确认”。
- 自动刷新与手动刷新；进程与端口的刷新都在后台线程执行，不阻塞界面。
- 点击进程/线程/端口表头可排序（详见下节“排序”）。
- 管理区按钮：刷新、查看来源/作用、结束选中进程、结束选中线程。
- 权限不足、进程退出、PowerShell 失败等都有容错，不会让程序崩溃。

## 排序

- 进程、线程、端口三个列表的每个表头都支持点击排序：第一次点击升序，再次点击
  降序。
- 当前排序列会在表头显示 `▲`（升序）或 `▼`（降序）。
- 排序状态会保留：自动/手动刷新后仍按上次选择的列与方向重新排序。
- 数字列（PID、父 PID、线程数、线程 ID、优先级、端口号）按数值排序，其余按文本
  排序；创建时间按字符串排序，缺失时显示“未知”并排在最后。

## 端口占用（只读）

端口页数据来源：

- TCP/UDP 连接与监听：`Get-NetTCPConnection` / `Get-NetUDPEndpoint`；
  命令不可用时自动回退到 `netstat -ano`。
- 进程名 / 父 PID / 路径：`Get-CimInstance Win32_Process` 按 PID 映射。
- 签名：点击端口行时按需读取 `Get-AuthenticodeSignature`。

端口页提供后台刷新（不阻塞界面）、手动刷新、搜索过滤、表头升序/降序。端口数据
仅用于观察，**不提供**关闭端口、停止监听或任何网络修改动作。端口只属于进程，
不代表某个具体线程；同一个进程可能有多个线程，端口本身不直接对应线程。

## 结束进程 / 线程

管理区的“结束选中进程”和“结束选中线程”按钮用于终止当前选中的目标。为避免误操作，
流程如下：

1. 先在列表中选中进程或线程。
2. 点击对应按钮后，会弹出确认框，显示目标名称、PID 或 TID，并附风险提示。
3. 只有点击“是”才会执行；直接关闭确认框或点击“否”都不会执行任何操作。
4. 成功会写入状态栏；失败会显示“拒绝访问（权限不足）”“目标可能已退出”等明确错误。

实现方式为 ctypes 调用 `kernel32.TerminateProcess` / `kernel32.TerminateThread`，
调用前使用 `OpenProcess` / `OpenThread` 获取句柄，结束或失败后始终关闭句柄。

风险边界（重要）：

- 结束进程会立即终止该进程及其所有线程，未保存的数据可能丢失。
- 结束线程可能导致所属进程状态不一致、崩溃或数据损坏。
- 结束系统关键进程/线程可能导致系统不稳定。
- 操作立即生效，通常不可撤销；请仅在你明确理解风险且确认目标正确后执行。
- 本工具不提供暂停、注入、提权、后台驻留等额外能力，也不代表可以安全结束任意
  系统目标。

## 数据来源与字段说明

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| 进程列表 | `Get-CimInstance Win32_Process` | PID、名称、父 PID、线程数、创建时间、可执行路径 |
| 线程列表 | `Get-CimInstance Win32_Thread` | 线程 ID、`ThreadState`、`ThreadWaitReason`、优先级 |
| 线程创建时间 | `kernel32.GetThreadTimes`（ctypes） | 需 `THREAD_QUERY_INFORMATION` 权限；系统/受保护进程的线程通常取不到，显示“未知” |
| TCP/UDP 端口 | `Get-NetTCPConnection` / `Get-NetUDPEndpoint` | 协议、本地/远端地址与端口、状态、所属 PID；不可用时回退 `netstat -ano` |
| 端口进程信息 | `Get-CimInstance Win32_Process` | 按 PID 映射进程名、父 PID、路径 |
| 代码签名 | `Get-AuthenticodeSignature` | 仅选中进程或点击端口行时按需读取，状态与签署者 |
| 结束进程/线程 | `kernel32.TerminateProcess` / `TerminateThread` | 仅用户点击并确认后执行 |

线程状态与等待原因的取值按公开文档约定映射为中文，例如“等待 / UserRequest”。

线程没有独立的可执行文件来源，其来源继承自所属进程。选中线程后，详情栏会展示
线程 ID、状态、等待原因，以及所属进程的路径、父 PID、签名与用途解释。端口同样
只属于进程：点击端口行会展示所属进程的来源路径、父进程、签名与用途依据，并提示
端口不代表具体线程。

## 用途解释规则（透明）

解释按以下顺序判断，依据会显示在界面上，避免“看起来像结论”的猜测：

1. 进程名命中内置的常见 Windows 组件表（如 `svchost.exe`、`explorer.exe`），
   给出“内置进程名规则”依据。
2. 路径位于 `System32` / `SysWOW64` / Windows 目录，给出“路径规则”依据；
   若同时 Microsoft 签名有效，标注“签名规则(Valid/Microsoft)”。
3. 签名有效但非系统目录，标注“已签名，可能为已安装软件”。
4. 未签名或签名异常，标注来源可信度未知。
5. 以上都不命中，显示“未知/需人工确认”。

进程名规则只是常见组件的提示，不代表可信性证明；是否可信应结合路径与签名
综合判断。

## 边界与限制

- 需要能执行 `powershell.exe`（Windows 10/11 自带）。
- 受保护进程（如 System、lsass）的可执行路径、线程创建时间、签名可能取不到，
  会显示“未知”，这是正常的权限边界，不代表程序出错。
- 线程状态与端口状态是瞬时快照，刷新后可能变化。
- 结束进程/线程依赖当前用户权限；对更高权限或受保护目标通常会返回
  “拒绝访问（权限不足）”，程序不会尝试提权。
- 端口页只读，不提供关闭端口、停止监听或任何网络修改动作。

## 文件说明

- `thread_monitor.py`：主程序（界面 + 进程/线程采集 + 端口页 + 解释规则 + 排序 +
  结束操作 + 自测）。
- `port_monitor.py`：端口采集数据层（Get-NetTCPConnection / Get-NetUDPEndpoint +
  netstat 兜底），并共享签名与用途解释逻辑，供主程序复用。
- `run_monitor.bat`：启动脚本。
- `docs/superpowers/specs/2026-09-26-thread-monitor-design.md`：设计文档。
